# v0.1 测试阶段

## 自动检查

```powershell
pwsh -NoProfile -File scripts/Inspect-Game.ps1
pwsh -NoProfile -File scripts/Build.ps1
pwsh -NoProfile -File scripts/Scan.ps1
npm run check
npm run build
npm test
```

Node 测试使用项目 `.cache/tests/` 中的隔离目录和文件通信测试端，覆盖通信与客户端行为。C# 行为通过实际游戏进程验证，测试端的结果不计入完整营业日验收。

当前自动测试覆盖普通往返、并发相同 ID、不同参数冲突、必需状态版本和会话、超时查询、旧会话的不确定结果、孤立意图恢复、不完整 JSON、离线和异常回执、CLI 子进程及 MCP stdio 初始化与工具调用。MCP 自动检查目前使用 2025-06-18 握手。

## 人工入口

1. 启动 Steam 版游戏，在模组菜单启用 `PSAI - Probably Stolen Agent Interface`。
2. 退出后重新启动游戏，载入独立的普通难度测试存档。
3. 记录启用的其他模组及测试存档所在天数。与公平信息规则或操作逻辑冲突的模组需要先处理。
4. 通知 agent 存档已载入。此后由 CLI 读取状态并继续验证。

本机桥接包已复制到游戏 `Mods/psai/`。启用和载入由用户完成，因为本会话按约定排除 CU，且需要用户确认测试存档。

## 实机验收顺序

- 检查 `status.json` 持续更新、协议版本、当前会话和 ready 状态，以及 Player.log 中的 `PSAI heartbeat active.` 记录。
- 连续观察两次，核对相同游戏状态的 revision 稳定。进入新存档或返回主菜单时检查 session 切换。
- 调用 begin_control，确认手动对话和叫号生效。检查可见对话、选择、物品名称、数量和当前面板文字。
- 执行一条对话或叫号动作，重新观察。重复同一命令 ID，确认只执行一次，错误版本与会话应被拒绝。
- 验证物品移动的完整与部分转移、容量不足、归属限制，以及正常激活和容器显示。
- 使用当前列出的交易、议价与确认按钮，完成至少一笔交易。核对现金、物品和成交日志。
- 推进关店、晚间报告、睡眠和次日面板，记录完整营业日。
- 在稳定决策点等待 30 秒和 120 秒，检查后台运行、对话和顾客变化。
- 补充异常请求、动画忙碌、重启后的 pending 结果，以及 end_control 的选项恢复。

## 首次加载发现的问题

2026-11-10 的日志确认 PSAI 已加载。初版在 IMod.OnEnable 中调用 ModHelper.StartCoroutine，当时加载器尚未将模组登记为运行中，该方法直接返回 null。心跳从未启动，因此客户端显示 bridge_not_started。

修复将轮询交给本模组创建的持久 MonoBehaviour.Update，确保在加载器完成登记后执行，并让 OnDestroy 调用幂等停止流程。重启后已确认心跳、ready 状态和观察请求成功。

后续已通过 begin_control、重复命令去重、过期 revision 拒绝、开店及第一位顾客到达观察。测试存档初始为第 1 天、450 信用点，第一位顾客为导师。实机回执位于 artifacts/live。

导师开场后发现手动等待状态下接口漏列 dialogue_advance。修复移除了对 isConversationActiveFlag 大于零的依赖，并增加顾客到达期间的 busy 条件。修复后已逐句推进导师对白，并完成后续买卖顾客的需求对白。

用户确认载入会回到当天起点。重载测试以新会话、第 1 天早晨、450 信用点重新建立基线。已验证两张赠送笔记转移、正常购买 25 信用点食物及成交命令重复提交不重复扣款。以 30 信用点正常卖出后现金为 455。

报价决策点静置 30.29 秒、累计 120.75 秒，revision 均保持 65，现金、报价和预算未改变。伦警官必要事件和关店也已完成。当前缺口为日结入口，原因是卷帘门夜间按钮锁被误作全局 busy。新修复通过编译、50 方法扫描和 11 项客户端测试，待更新后验证。

脚本已通过语法与严格 TypeScript 检查，完整实机运行仍待完成。夜间按钮标签如与当前匹配模式不同，应根据当前可见标签适配，保留当天状态继续验证。
